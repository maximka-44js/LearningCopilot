## 1. Действие: регистрация и первый вход в систему

**Сценарий:**
1. Пользователь открывает веб‑приложение и нажимает кнопку "Регистрация".
2. Система открывает форму регистрации через единый сервис входа.
3. Пользователь заполняет форму (email и пароль) и подтверждает регистрацию.
4. Система проверяет корректность данных и показывает ошибки при необходимости.
5. При успешной регистрации система создаёт учётную запись и возвращает пользователя в приложение.
6. Пользователь входит в систему и попадает на страницу проектов.
7. Система предлагает создать первый проект — главную цель обучения.
8. Пользователь задаёт имя проекта и краткую цель (например, "Подготовка к экзамену по матану").
9. Система создаёт проект и предлагает добавить первый стейдж (этап).


## 2. Действие: создание новой библиотеки конспектов

**Сценарий:**
1. Пользователь открыет раздел "Библиотеки".
2. Пользователь нажимает "Создать библиотеку".
3. Система показывает форму: название, описание и тип доступа.
4. Пользователь вводит название и при необходимости добавляет описание.
5. Пользователь выбирает режим доступа: "приватная" или "публичная".
6. Для приватной библиотеки пользователь добавляет контрибьюторов по нику.
7. Пользователь назначает права контрибьюторам (просмотр/редактирование).
8. Система проверяет корректность введённых данных и показывает результат добавления.
9. Пользователь подтверждает создание; библиотека доступна для прикрепления к проектам и стейджам.


## 3. Действие: загрузка учебного материала

**Сценарий:**
1. Пользователь открыет нужную библиотеку.
2. Пользователь нажимает "Загрузить материал".
3. Система предлагает выбрать файл (txt, md, pdf или изображения) и ввести название.
4. Пользователь выбирает файл и подтверждает загрузку.
5. Система проверяет формат и доступность файла.
6. Если файл не подходит, система показывает причину и предлагает выбрать другой.
7. Если файл подходит, система добавляет материал в библиотеку и подготавливает его для использования.
8. Система показывает статус "Материал готов" и теги/метаданные.
9. Пользователь видит документ в списке материалов библиотеки и может прикрепить его к стейджу.



## 4. Действие: получение объяснения темы через RAG-тьютора

**Сценарий:**
1. Пользователь открыет чат с тьютором внутри выбраного стэйджа или проекта.
2. Система предлагает выбрать файл из библиотеки или загрузить новый.
3. Пользователь выбирает источники и задаёт вопрос по теме.
4. Система формирует ответ по найденным фрагментам и показывает ссылки на них, если ресурс был векторизирован или он не больше 10МБ.
5. Система предлагает либо уточнить вопрос, либо подключить дополнительные материалы если не уверена, что материалов хватит.
6. Пользователь выбирает подходящий вариант.
7. Система обновляет ответ и выделяет, какие части подтверждены материалами.
8. Пользователь неявно завершает, удаляет или продолжает диалог.

## 5. Действие: генерация квиза по выбранному материалу

**Сценарий:**
1. Пользователь открывает проект и выбирает стейдж, в котором нужно проверить прогресс.
2. В стейдже пользователь нажимает "Создать квиз" или добавляет квиз к таску.
3. Система предлагает выбрать материалы из доступных библиотек для этого стейджа(библиотеки проекта + библиотеки стэйджа).
4. Пользователь задаёт типы вопросов, количество заданий и ожидаемый результат для таска.
5. Система проверяет достаточность материалов и предупреждает, если их мало.
6. Если материалов недостаточно, пользователь добавляет источники или корректирует параметры.
7. Пользователь подтверждает параметры генерации.
8. Система создаёт квиз и привязывает его к указанному стейджу/таску, показывая предпросмотр.
9. Пользователь сохраняет набор; задача‑квиз появляется в списке задач стейджа.

## 6. Действие: прохождение квиза и автоматическая проверка

**Сценарий:**
1. Пользователь открывает карточку таска‑квиза в стейдже и нажимает "Начать".
2. Система показывает правила прохождения, цель таска и таймер (если включён).
3. Пользователь последовательно отвечает на вопросы разных типов.
4. Система сохраняет ответы по мере прохождения, чтобы не потерять прогресс.
5. После завершения пользователь отправляет ответы на автоматическую проверку.
6. Система проверяет закрытые вопросы и формирует предварительный отчёт.
7. Для развёрнутых ответов система предоставляет критерии оценки и пометки для ревью.
8. Система присваивает статус таску (выполнено/требует доработки) и обновляет прогресс стейджа.
9. Пользователь изучает разбор ошибок и при необходимости создаёт ремедиационные таски.

## 7. Действие: разбор ошибок в диалоговом режиме с квизером

**Сценарий:**
1. После завершения таска‑квиза пользователь в карточке задачи нажимает "Разобрать ошибки".
2. Система формирует список вопросов, где были неточности или неверные ответы.
3. Пользователь выбирает конкретный вопрос для разбора.
4. Система показывает ответ пользователя, правильный ответ и фрагмент источника.
5. Пользователь задаёт уточняющий вопрос: "Почему мой вариант неверен?".
6. Система объясняет различия и указывает ключевые признаки правильного ответа.
7. Если пользователь всё ещё затрудняется, система предлагает мини‑упражнение или дополнительный материал.
8. Пользователь выполняет мини‑упражнение прямо из карточки таска.
9. Система обновляет статус таска и прогресс стейджа в зависимости от результатов.

## 8. Действие: просмотр истории диалогов и сохранённых квизов

**Сценарий:**
1. Пользователь открывает раздел "История" проекта или стейджа.
2. Система показывает вкладки: "Диалоги", "Квизы", "Результаты" и фильтр по стейджам/таскам.
3. Пользователь фильтрует историю по конкретному стейджу или типу таска.
4. Система показывает связанные квизы, кто выполнял и к каким задачам они относились.
5. Пользователь открывает нужный квиз/попытку и просматривает детали.
6. Система восстанавливает контекст: связанный стейдж, материалы и участники.
7. Пользователь может клонировать квиз в новый таск или запустить повтор для выбранного стейджа.
8. Система сохраняет новую попытку и привязывает её к стейджу/таску.
9. Все изменения отражаются в истории проекта и доступны для отчёта.

## 9. Действие: отслеживание прогресса и проблемных тем

**Сценарий:**
1. Пользователь открывает дашборд проекта.
2. Система показывает общий прогресс: процент выполнения стейджей и задач, включая квиз‑таски.
3. Пользователь видит список активных, просроченных и завершённых тасков по стейджам.
4. Система выделяет стейджи‑узкие места и показывает, какие квиз‑таски снижают прогресс.
5. Пользователь выбирает проблемный стейдж и просматривает связанные квизы и попытки.
6. Система предлагает персональные шаги: назначить ремедиацию, добавить материалы или создать повторный квиз‑таск.
7. Пользователь редактурует план действий по стейджу и подтверждает изменения.
8. Система обновляет расписание проекта, уведомляет участников и пересчитывает прогресс.
9. Изменения сохраняются в истории проекта и влияют на общие метрики.
