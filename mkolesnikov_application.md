[ НАЗВАНИЕ ПРОЕКТА ]

"Learning Copilot – система управления долгосрочными академическими целями"

[ ПРОБЛЕМНОЕ ПОЛЕ ]

При работе над большими академическими целями, такими как подготовка к экзамену, изучение сложной дисциплины или освоение новой области знаний, обычных TODO-листов недостаточно. Они позволяют отмечать выполненные задачи, но не учитывают постепенное забывание изученного материала и не позволяют оценить текущую готовность пользователя.

Заявляемый продукт решает эту проблему с помощью иерархической модели академических целей. Пользователь создаёт проект с главной целью, разбивает его на этапы (stages), а каждый этап — на отдельные задачи.

Для каждой задачи учитываются три составляющие подготовки: понимание материала, запоминание и практика. Пользователь может задавать относительный вес каждой составляющей, а также параметры угасания готовности. Предполагается, что готовность к задаче со временем уменьшается по экспоненциальной функции.

На основе этих данных и времени, прошедшего с момента последней работы над задачей, система рассчитывает две основные метрики: readiness, показывающую предполагаемую текущую готовность, и coverage, показывающую, какая часть цели когда-либо была проработана без учёта времени.

Метрики автоматически суммируются на уровне этапов и проектов, что позволяет пользователю видеть не только список выполненных задач, но и общее состояние подготовки к большой академической цели.

[ ЗАКАЗЧИК / ПОТЕНЦИАЛЬНАЯ АУДИТОРИЯ ]

Целевая аудитория продукта:

* Школьники и студенты, готовящиеся к экзаменам и другим проверочным мероприятиям
* Студенты, работающие над долгосрочными академическими целями
* Самообучающиеся пользователи, изучающие новые области знаний
* Пользователи, которым необходимо разбивать большие учебные цели на этапы и небольшие задачи

[ АППАРАТНЫЕ / ПРОГРАММНЫЕ ТРЕБОВАНИЯ ]

Продукт разрабатывается как веб-приложение, доступное через браузер:

* Браузеры: Chrome (версия 90+), Firefox (версия 88+), Safari (версия 14+), Edge (версия 90+)
* Интернет-соединение для работы с веб-приложением
* Рекомендуемое разрешение экрана: от 1280×720 (интерфейс адаптивный)
* Серверные требования: PostgreSQL 14+, Go 1.24+

[ ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ ]

Программный продукт будет предоставлять следующие возможности:

* Регистрация и авторизация пользователей
* Создание и управление проектами с главной академической целью
* Разбиение проектов на этапы (stages)
* Создание и управление задачами внутри этапов
* Настройка параметров угасания для проектов, этапов и задач
* Оценка задач по трём составляющим: понимание, запоминание и практика
* Настройка пользователем весов для каждой составляющей
* Расчёт метрики readiness с учётом оценок, весов и времени, прошедшего с последней работы над задачей
* Расчёт метрики coverage, показывающей накопленный объём проработанного материала
* Агрегация показателей задач на уровне этапов и проектов
* Просмотр текущего состояния подготовки и прогресса по проекту
* Хранение истории работы с задачами, необходимой для расчёта показателей
* Отдельный раздел материалов для хранения учебных файлов
* Создание библиотек, папок и файлов
* Предоставление другим пользователям доступа к материалам
* Управление API-ключами для доступа к API сервиса
* Возможность использовать API сервиса во внешних интеграциях, например с ИИ-агентами. Разработка самих ИИ-агентов и интеграций в рамках проекта не предполагается.

[ ПОХОЖИЕ / АНАЛОГИЧНЫЕ ПРОДУКТЫ ]

Анализ существующих решений показал следующее:

* Todoist / TickTick: позволяют управлять задачами и проектами, но не учитывают изменение академической готовности пользователя со временем.
* Notion: позволяет создавать системы из задач и баз данных, однако специализированная модель оценки готовности и покрытия требует самостоятельной реализации.
* Anki: предназначен в первую очередь для интервального повторения и запоминания отдельных элементов материала, но не предоставляет иерархической модели больших академических целей.
* Обычные файловые хранилища: позволяют хранить учебные материалы, однако не связывают их с системой управления академическими целями и оценкой готовности.

[ ИНСТРУМЕНТЫ РАЗРАБОТКИ, ИНФОРМАЦИЯ О БД ]

* Go – backend и REST API
* PostgreSQL – хранение пользователей, проектов, этапов, задач, оценок, истории и материалов
* React / Next.js – frontend веб-приложения
* Docker – контейнеризация и развёртывание
* REST API – взаимодействие frontend с backend и возможность внешнего доступа к функциям сервиса
* Математическая модель на основе экспоненциальной функции – расчёт угасания готовности и показателей readiness

[ ВОЗМОЖНЫЕ РИСКИ ]

* Реальное забывание материала может отличаться от используемой математической модели. Для этого параметры угасания делаются настраиваемыми пользователем.

* Оценки понимания, запоминания и практики являются субъективными. Система рассматривает их как пользовательские оценки, на основе которых рассчитывается ориентировочная готовность.

* При большом количестве задач расчёт и отображение агрегированных показателей может потребовать оптимизации запросов к базе данных.

* Необходимо обеспечить безопасную работу с пользовательскими данными и API-ключами.

* При разработке файлового хранилища возможны ограничения на поддерживаемые типы файлов и их размер.

* Внешние интеграции, включая использование API сервиса ИИ-агентами, не входят в основную функциональность проекта и рассматриваются как возможность дальнейшего использования API.
